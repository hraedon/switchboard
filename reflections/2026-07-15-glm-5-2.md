## On the project

switchboard's architecture continues to hold up well under feature pressure. The pure routing core (`control.py`) absorbed the token-budget dimension cleanly — one new field on `ProviderState`, one new threshold on `RoutingConfig`, and the same `low_headroom or over_budget` pattern in `route_decision`. The layered routing decision (gate → overload → low-interactivity → headroom → token-budget → model → affinity) is now six signals deep, and each is independently testable and opt-in. That's the project's core strength.

The new `UsageObserver` is the project's first response-body reader. This is a deliberate, documented narrowing of the "inert in-path" constraint — read-only observation of the `usage` object only, bytes forwarded unchanged. It's analogous to the proxy already reading response status codes and headers. The constraint documentation in AGENTS.md now has three narrow exceptions (model-map request rewrite, model-map cache-transparency waiver, token-budget response observation), all opt-in and gated. The pattern is established.

The HistoryStore wiring exposed a friction point: `sluice.history.History` and `sluice.history_store.SQLiteHistoryStore` are designed for a single-provider deployment. switchboard needs per-provider stores, and `SQLiteHistoryStore` hardcodes the table name `history`. I worked around this by creating separate files per provider (`<store>.<name>.history`), which is clean but means N connections to N files. A future sluice API change to accept a table-name parameter would let switchboard share one connection.

## On the work done

**What went well:** The adversarial review process caught significant bugs that local tests missed. The CRITICAL `_acquire_with_disconnect` body-eating bug would have silently broken every queued request without a model map — the reviewer wrote a test that proved it. The History `__len__` crash would have broken `/status.json` in production the first time someone configured a route-table store. Both were invisible to the test suite because the tests didn't exercise those code paths.

**What was awkward:** The MockTransport + streaming interaction required trial and error. `httpx.Response(content=...)` doesn't support `aiter_raw()` through MockTransport — you need `stream=` with a custom `AsyncByteStream`. This is a test-infrastructure issue, not a code issue, but it slowed down the integration tests. The pattern is now established in test_integration_plan012.py for future tests.

**What I'm confident in:** The pure core (`budget.py`, `route_decision` filtering) is well-tested and correct. The read-only guarantee of `UsageObserver` is verified — bytes forwarded are never modified. The LRU affinity is correct (`OrderedDict.move_to_end` + `popitem(last=False)`). The disconnect-during-queue fix correctly gates on `body_buffered`. The config validation is complete for all `[token_budget.*]` fields.

**What I'd want a second pair of eyes on:** The `_acquire_with_disconnect` watcher still consumes `receive()` events (body events included) — it's only safe because it's gated on `body_buffered=True`. If someone later changes the gating condition without understanding why, the body-eating bug returns. The comment explains it, but the coupling is subtle. Also, the per-provider `soft_threshold` from `[token_budget.*]` config is parsed, validated, and displayed in status, but the routing core uses the global `token_budget_threshold` — the per-provider value is dead config. This is documented in the review findings but not yet fixed.

## Gaps to flag

- **Per-provider `soft_threshold` is dead config** — parsed, validated, displayed, but the routing core uses the global `token_budget_threshold`. An operator who sets `soft_threshold = 0.80` per-provider and `token_budget_threshold = 0.85` globally gets 0.85 for all providers. `control.py:338-339`, `budget.py:53`
- **`_acquire_with_disconnect` has no dedicated unit test** — verified by the reviewer's test but not permanently in the test suite. The `body_buffered` gate is the safety mechanism; a regression test should assert that `receive()` is NOT called when `body_buffered=False`. `proxy.py:854`
- **Monotonic clock persistence** — `TokenBudgetTracker` persists timestamps as monotonic. On Linux, `CLOCK_MONOTONIC` is per-boot, so this works across process restarts but not across system reboots. After a reboot, old samples may appear "fresh." Self-corrects after one window period. `token_budget.py:221`
- **HistoryStore file collision** — `_safe_filename` normalizes provider names for filenames. Distinct names like `provider/foo` and `provider:foo` both normalize to `provider_foo`, causing two providers to share one history file. `providers.py:361-367`
- **Non-SSE response buffer** — `non_sse_buf` accumulates non-streaming response bytes (capped at 1 MB). If an upstream sends a very large JSON response with usage at the end, the buffer grows to the full response size (up to 1 MB). `proxy.py:1198-1200`
