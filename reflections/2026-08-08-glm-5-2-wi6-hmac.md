## On the work done

**WI-6 (edit-provider form).** Generalized `renderProviderForm(existing)`
to an optional edit mode: a per-card Edit button opens the form pre-filled
from `GET /admin/providers` (the masked store row — the tier the PUT
writes, not the env-merged view), with env-locked fields disabled per
`GET /admin/config/effective` `env_locked` (Plan 021 WI-7 provenance).
Write-only stored-key semantics; full editable field set. The adversarial
pass caught **four** bugs, all fixed: (1, HIGH) TOML provider `type`
misread as `provider_type` → silent rewrite to `generic`; (2) TOML-stored
keep-on-blank 400s (no store row); (3) `account` reset to default; (4)
stale `editingProviderName` could PUT one provider's config under another's
name — fixed with an `editToken` reentrancy guard. GUI harness 42 → 68
checks. The admin PUT handler is unchanged — pure GUI WI.

**HMAC route keys (Plan 008 §3).** `hash_route_key(raw, secret=None)` is
HMAC-SHA-256 with a secret, plain SHA-256 without (byte-identical backward
compat). Rotation via `SWITCHBOARD_ROUTE_KEY_SECRET_PREV` dual-read window:
`_match_route` tries current then previous secret, returns
`(providers, matched_digest)`. The adversarial pass caught the **HIGH**
bug: `_match_route` first returned only providers while `hashed_key` was
always the current-secret digest, so a previous-secret match was
re-resolved under the current secret at `route_decision` → missed → fell
to default → 503ed healthy keyed traffic for the whole rotation window.
Fixed by returning the matched digest. Env-only sourcing; secret never
logged/serialized/sent upstream; boot warning when HMAC enabled with
existing plain-digest entries.

**On the adversarial-review discipline:** both reviews earned their cost.
WI-6's review caught a HIGH that would have silently corrupted TOML
providers on edit; HMAC's review caught a HIGH that defeated the feature's
core promise. The pattern (implement → deepseek review → fix → push) is
the right one for this repo and should be the default for anything
touching the live path or security-sensitive surfaces.

## Gaps to flag

- **HMAC rotation leaves dead SQLite rows.** Re-adding a key under a new
  secret inserts a new row keyed by the new digest; the old-digest row
  lingers and becomes unreachable once `_PREV` is dropped. Documented in
  the plan; no cleanup machinery built (out of scope for §3). An admin
  affordance or a re-add that deletes the old-digest row would close this.
- **Plain→HMAC adoption has no read window.** The dual-read covers
  secret-A→secret-B rotation only. Enabling HMAC on a deployment with
  existing plain-digest entries (TOML `[route.*]`, pre-HMAC SQLite rows)
  orphans them silently → they fall to the default route. A boot warning
  fires, but there's no automatic migration. Deliberate (a plain fallback
  would weaken the security model and can't be turned off), but operators
  must re-add routes manually.
- **`max_request_body_bytes` still unbounded by default** (carried from
  session 1's reflection — unchanged). The model-map buffering path has
  the same memory-exhaustion surface pinning flagged.
- **`p50` speed metric computed but not surfaced** (carried from session 1
  — unchanged). Dead data in the status.json payload.
- **GUI still has no integration test against a real ASGI server** (carried
  from session 1 — unchanged). The edit form is shim-tested only.
